# 加拿大 16 天行程 App — 部署到 GitHub Pages

不需要任何安裝或建置步驟，直接部署到 GitHub Pages（完全免費）。

## 部署 / 更新步驟

你已經有部署好的 repo，這次**只需要覆蓋更新**：
1. 解壓縮這個 zip
2. 回到你 GitHub 上的 repo → 把裡面所有檔案拖進去上傳（檔名相同會自動覆蓋）
3. 填 commit message → `Commit changes`
4. 等 1–2 分鐘，GitHub Pages 自動更新，手機上已安裝的 App 重新整理就會是新版本

首次部署者：GitHub 建 public repo → 上傳全部檔案 → Settings → Pages → Deploy from branch (main, /root) → 拿到網址 → 手機瀏覽器打開 →「加入主畫面」。

## 上一輪更新的內容

### 🐛 修好了「上傳新版但App還是舊的」問題
這不是你操作錯誤，是App本身的bug。原因：App有離線功能，靠一個叫Service Worker的東西把首頁/app.js快取起來，但快取策略之前寫的是「快取優先」——只要瀏覽器裡已經存了一份，之後就永遠優先讀那份快取，不會去檢查GitHub上是不是有新版，除非你手動清快取。

已經修正成「連網優先」：只要你手機有網路，每次打開都會先去抓最新版本，只有真的斷網時才會退回去用快取的舊版本（離線功能還是保留）。也加了自動偵測新版就重新整理一次的機制。

如果這次上傳後畫面還是舊的，代表手機裡還卡著更早之前的Service Worker：iPhone/Android瀏覽器設定裡找到這個網址清除資料，或桌機Chrome長按重新整理鈕選「清空快取並重新載入」；加到主畫面用的話，把捷徑刪掉、瀏覽器資料清乾淨、重新「加入主畫面」一次。之後的更新就不用再處理這件事了。

### 卡片摺疊/精簡模式
右上角新增一個開關，點下去所有卡片收合成單行，點單張卡片可以個別展開。開關會記住設定。

## Google Maps API 金鑰安全性提醒 ⚠️

金鑰已經寫進 `app.js` 裡，任何人檢視網頁原始碼都看得到這把金鑰。**這是正常且無法避免的**（前端網頁本來就是這樣），但你必須做以下設定才安全：

1. 前往 https://console.cloud.google.com/apis/credentials
2. 找到你這把金鑰，點進去編輯
3. 「應用程式限制」選「HTTP 轉介網址（網站）」
4. 新增你的 GitHub Pages 網址，例如 `https://你的帳號.github.io/*`
5. 「API限制」勾選只允許 `Maps JavaScript API`

這樣即使金鑰外流，別人也只能在你的網站網域使用，無法盜用去別的地方產生費用。**強烈建議現在就去設定**，這比什麼都重要。

## Firebase 多人同步

已經接上你的 Firebase 專案（`canada-trip-ae7c8`），記帳分帳資料現在會即時同步給所有打開這個網址的人。第一次使用建議：

1. 打開「記帳本」分頁，先點右上「設定」選你是誰
2. 之後新增的每一筆支出都會自動記錄是誰輸入的

### Firestore 安全規則建議

目前若是用「測試模式」建立的資料庫，規則預設30天後會自動關閉讀寫。建議去 Firebase Console →
Firestore Database → 規則，貼上以下內容並發布，讓規則長期有效（allow open read/write，
適合8人小型行程，不需要登入機制）：

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /canadaTrip/{document} {
      allow read, write: if true;
    }
  }
}
```
